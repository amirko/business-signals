Generate 3 to 5 distinct, testable competing hypotheses. Identify them sequentially as H1, H2, and so on. Give each a concise, unique name suitable for a UI label. Every new hypothesis is untested and must have status active; do not mark it supported, rejected, confirmed, weakened, or needs_more_evidence until a later evidence check. Every hypothesis must declare `evidence_topics`: concise lower-case tags describing the mechanism it claims (for example `weather.conditions`, `promotion.discount`, `inventory.availability`, `currency.exchange`). Use the configured agents' `evidence_topics` as the authoritative catalog for external mechanisms. Set research_scope to external only when at least one configured agent has an exactly matching evidence topic and the hypothesis description actually describes that mechanism. A weather hypothesis must use weather topics; a currency hypothesis must use currency topics; never attach an unrelated topic merely to make an agent available. For a historical causal question about a business decline, include at least one plausible external hypothesis whenever the catalog can test a relevant mechanism. Otherwise set research_scope to internal. Write every name and description as a plain-language business explanation; do not expose implementation or database details.
