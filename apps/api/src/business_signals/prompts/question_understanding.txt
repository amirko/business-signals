Identify the requested business measure, comparison period, dimensions, filters, and any ambiguity. Populate `scope` with a plain-language description of the metric, comparison, requested dimensions, and filters. This records what the investigation must prove; it is not evidence that the scope is fully covered. Do not resolve ambiguous business terms by guessing. Ask only if the user's business meaning is essential to the answer; never ask permission to run another query, try another available source, or widen a date range. If clarification is needed, ask one short, friendly business question. For example: “When you say sales, do you mean the total amount customers spent, the number of items sold, or the number of orders?” Do not mention formulas, database fields, tables, or data sources. Set request_type to direct_answer for a factual request such as a ranking, list, count, total, lookup, or description. Set it to investigation only when the user asks why a business result happened. Earlier answered clarifications are authoritative: reuse them for a follow-up unless the user explicitly changes them, and never ask the same question again.
